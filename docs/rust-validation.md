Packager tests reject malformed architecture/class/endian/type, wrong interpreter, invalid executable entry or PIE flag, malformed/bounded headers, writable executable loads, an executable GNU_STACK and insufficient alignment on any load. They also cover exact archive ordering/modes/timestamps/checksum, identical repeated archives, missing notices, duplicate/wrong module identity, CRLF shell files, invalid WASM, unknown private files/directories, Windows junctions, unsafe output/sidecar paths and guarded byte-asset generation. The ZIP byte asset is regenerated from the actual included WASM; stale source bytes and generated declaration files cannot enter the release.

The browser harness checks that private API URLs, authentication fields, provider bodies and hidden stack lists never enter the rendered interface or bridge arguments. Fetch remains a separately requested backend action followed by manual Validate; it never selects a key or submits Plan/Apply automatically. Stack changes require explicit profile/package/scope choices, a separate reviewed Apply, file verification and separately confirmed rollback. User/configuration/stack evidence changes invalidate readiness declarations and plans. File readback keeps runtime adoption and Wallet acceptance unknown. Reset confirmation remains separate and bound to the reviewed numeric Android user; nothing reboots or continues a reset automatically.

Stack resolution preserves the current resource and prior journal without rewriting that resource. Incomplete-reset closure preserves every attempted-step field and never repeats a clear. Both require an exact phrase and reviewed hash, reject stale evidence, preserve strict private terminal evidence and support matching idempotent replay. New terminal states fail closed in the older Go implementation; downgrade compatibility requires review. Ordinary rollback guards remain unchanged. The Android trust pool uses bounded approved system stores only, skips unusable individual roots and fails if none remain. Windows fixtures cannot establish actual Android filesystem or HTTPS behavior.
