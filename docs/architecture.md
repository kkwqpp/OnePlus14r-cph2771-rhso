# Architecture and interface

RHSO v0.2.0 is an explicitly invoked helper around the existing TrickyStore, HMA-OSS and BreZygisk installation. WebUI, native CLI, module action and Windows ADB use one Go backend and dispatcher. The module installs no daemon, TCP service, filesystem mount, startup writer, attestation provider, property spoof, scheduled rotation or reboot hook. It cannot write bootloader state or partitions.

```text
KSU WebUI / module action / root CLI / ADB
                  │
           command dispatcher
                  │
     inspect → stage → validate → plan
                  │
       lock + complete backup + journal
                  │
        apply → evidence verification
                  │
       rollback / interrupted recovery
```

The layers have distinct authority. Source adapters produce private staged material. Validators never apply it. Planning records bound hashes and deliberate selections. Transactions alone replace active configuration. Presentation code renders redacted structures with text nodes and has no separate mutation logic. The original API endpoint remains unavailable; the separate configured HTTPS raw-XML adapter has its own strict private schema. Hiding settings use a separate typed resource registry and journal.

## Command contract

All request arguments are strings. JSON is UTF-8, base64url encoded without padding, passed after the fixed `walletdiag request` entry point. The WebUI bounds request and response sizes, checks schema version and never places a raw path, XML, credential or API string into the shell command. Unknown commands/arguments are rejected by the dispatcher; the backend performs every independent authorization/path/validation check.

| Command | Arguments | Result and scope |
|---|---|---|
| `help` | Native CLI | Commands, usage and exits. |
| `init` | none | Initialize root-owned private directories; no active configuration mutation. |
| `status` | none | Current redacted configuration, fresh time, next step, history and recovery availability. |
| `diagnose` | none | Read-only evidence/findings before replacement imports. |
| `export` | none | Same bounded diagnostics, emitted as a redacted support result. |
| `ingest` | `path` | Copy allowed source to private staging; return ID/hash/time. |
| `validate` | `id` | Return `{id,sha256,summary}`; no active write. |
| `plan` | `selections`, `targets`, `compact-targets` (`true`/`false`), `patch` (empty or date) | Bind staged hashes, active hashes/existence, public/PIF/stack evidence, intended changes, adoption and recovery policy. |
| `apply` | `id` | Recheck plan, create complete backup, journal/apply and report verification evidence. |
| `verify` | Optional `wallet-ready`, `tap-confirmed` (`true`/`false`); numeric `reviewed-user` required for positive declarations | Recheck configuration/profile before recording personally confirmed checks; separate commit/health/adoption/Wallet results. Defaults remain unverified. |
| `trust` | `action` (`status`/`refresh`) | Explicit bounded Google public-feed refresh or local read-only chain check; no private input is uploaded. |
| `backups` | none | Redacted manifests/time/differences/verification state. |
| `rollback` | `id` | Previous, last recorded verified, or named backup; backs up current set first. |
| `api` | `action` (`status`/`config`/`import`), private inbox JSON `path` for config only | Redacted generic availability/configuration or explicit staging-only GET; no URL/token/password argument. Original endpoint remains unavailable. |
| `stack` | `action` (`status`/`plan`/`apply`/`verify`/`rollback`); `profile`, `targets`, `hide-packages`, `enabled`, `id` as appropriate | Typed selected-setting plans and backed-up writes; file readback/rollback; runtime activation unknown. |
| `watch` | `days` | Manual read-only warning window. |
| `recovery` | `action` (`status`/`restore`/`release-lock`) | Pending transaction/lock state, previous-set restoration or ended-owner lock release. |
| `reset` | `action` (`preview`/`status`/`confirm`/`resume`/`complete`), `confirmation`, `review_hash` when required | Separately reviewed, one-shot clears; manual reboot and PIF action; explicit completion record. |

Result: `{schema:1,ok:boolean,code:string,message:string,time:RFC3339,data:object}`. Native CLI also routes through this result layer. Exit-code classes: 0 success, 1 other IO/failure, 2 invalid input/selection/request, 3 busy, 4 stale plan/material, 5 missing capability/root/API, 6 missing confirmation, 7 recovery required. Error messages are safe and give a next step instead of printing raw cryptographic parser content.

## Persistent formats and compatibility

Persistent state resides outside the replaceable module folder, in `/data/adb/wallet_diagnostic`. The store marker is `format.json`, schema 1, kind `wallet-diagnostic-private-store`. The backend writes this marker only for a fresh empty store. Existing unsupported/corrupt markers, or unmarked nonempty state, fail closed with `E_FORMAT`; no implicit stamp, deletion or migration is performed. Private inventory, plans, manifests and journals also use schema versions. Reset review/journal additionally record `user` as a validated numeric Android user string and include it in the review hash; missing user binding is corrupt evidence, not permission to start a new ritual. Future migrations must back up old data before changing it. Updates/uninstall preserve this directory. No cleanup/pruning/deletion API exists.

`go.mod` declares Go 1.25 as the minimum; the tested official compiler is Go 1.27.2. The release is a native Android arm64 ELF (`GOOS=android`, `GOARCH=arm64`, `CGO_ENABLED=1`), using NDK r30 API-28 external linking and Android's system runtime for native DNS. KernelSU sets WebUI file permissions/contexts; installer overrides only executable files. Private state and active-file metadata are checked by backend platform code; production SELinux writes and filesystem recovery behavior must be distinguished from Windows fake tests and phone sandbox tests in the test report.

Target compatibility is the owner’s installed KernelSU-Next 3.3.0/uapi2 and TrickyStore 1.4.1 build245, with the installed standalone WebUI activity/bridge verified statically. Installed TS code accepts traditional EC/RSA private PEM and watches configuration files. This does not establish that all supported helper key parameters or metadata cases have been exercised on the phone. Real engine identity adoption and Wallet acceptance remain explicit evidence gaps.

The standalone APK’s file-picker callback exists statically, but returning a content URI is not a validated root-private ingestion contract. The release uses a private inbox path and ADB transfer. Module action resolves `io.github.a13e300.ksuwebui/.WebUIActivity`, launches with `id=wallet_diagnostic` when available, and falls back to read-only status and the exact CLI command. No randomized manager package is hardcoded.

## Testing and boundaries

Synthetic cryptographic fixtures and a harmless fake engine are required for offline tests. No real private material or credentials enter source control. See the test report for the actual commands/results; a test listed as a responsibility in this document is not a claim of real-phone execution. UI browser tests use an ephemeral loopback server on the PC and an inert mock bridge; no phone server/daemon is installed. Screenshots contain mock redacted data only.

The verified boundary is local workflow and recovery behavior under the documented fixtures/faults. External root writers, provider provenance/trust/revocation, Google policy, issuer/region/account eligibility, device SELinux behavior, real bridge execution and actual Tap-to-Pay require evidence outside those tests. Each remains separate from a successful XML parse, a file write or a generic integrity result.
