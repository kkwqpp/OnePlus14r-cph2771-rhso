1. Import into private staging

Copy an XML file to the private inbox using ADB, then enter its absolute path. The backend copies and validates it before it can enter a plan.

Private: /data/adb/wallet_diagnostic/inbox/name.xml. Optional /sdcard/keybox_inbox/name.xml is less private; remove the shared copy yourself after import.

How to copy a file

Use the Windows ADB examples in the first-use guide included in the download. This interface does not assume the host supports a browser file picker. Never paste XML or credentials into the UI.

2. Choose material deliberately

Choose at most one complete key and certificate chain per algorithm. A merged keybox contains only the entries you select: import the current active keybox and select its entries to retain an algorithm. Every Keybox and conflicting entry is listed separately. Trust and revocation stay unknown unless independently established.

Interrupted-operation recovery

If a stopped process left only a lock, the backend can release it after proving the owner ended or the boot changed. It refuses to release a running process’s lock.

Separately confirmed Wallet reset

This clears Wallet, Play Store, GSF and GMS app data. Wallet/card setup may be lost, GSF state/Android-ID behavior may change, and Google sign-in and card re-provisioning may be required. A manual reboot and reviewed PIF action are separate steps. The requested second GMS clear has no established rationale.

Use only after diagnosis supports trying this workflow. Reset is separate from ordinary Apply and rollback cannot restore cleared app data. Automatic post-reboot PIF execution is unavailable: the installed action fetches network material and can change PIF/patch settings. Review and run that action manually, then force-stop GMS. The helper only records your explicit completion.
