What do these terms mean?
Keybox
A file with private signing keys and certificate chains. Keep its contents outside this UI.
HMA
Hide My Applist. Its app scopes describe which packages selected apps should hide.
BreZygisk
A root-stack component. The supported setting here changes its unmount marker; it needs a manual reboot.
PIF
Play Integrity Fix. Its fingerprint and patch settings are separate from your keybox.
File verification
Checks saved configuration. Wallet approval and a successful payment need your own checks.

1. Import a private copy

A keybox contains private signing material. Import copies the XML for review; it does not replace your active files.

Use /data/adb/wallet_diagnostic/inbox/name.xml. The optional /sdcard/keybox_inbox/name.xml is less private; remove that shared copy yourself after import.

How to copy a file

Copy the file with ADB, enter its phone path above, then import it. Use the Windows examples in the first-use guide included in the download.

Keep XML, private keys and credentials in the file. Never paste them into this interface.

2. Choose the entries to keep

The new keybox contains only your selected entries. Choose at most one complete key and certificate chain per algorithm.

Keeping an existing algorithm

Import the current keybox and select the entries you want to retain. Conflicting entries are listed separately. Trust and revocation remain unknown unless checked independently.

Optional target and patch repairs

Choose a repair only when fresh findings support it. All options start unselected.

Other proposed repairs

Keeps the first entry, comments, blank lines and package modes. Conflicting modes or unsupported syntax stop the plan. Review every removal before Apply; this does not prove root hiding or Wallet approval.

Leave blank to keep the current patch. Match the configured PIF patch only when fresh findings justify it.

3. Review before applying

Apply rechecks this plan and backs up all three active files before changing them. External edits invalidate the plan.

Let a started change finish or use recovery. Closing the WebUI does not safely cancel a commit.

4. Check files, then Wallet

The helper reports saved files, engine health and adoption evidence separately. Fresh attestation traffic may still be needed.

Confirm the boxes only after your own checks in Wallet. A file check cannot approve a card or payment.

What these settings do

HMA adds packages to explicitly selected app scopes. Existing private lists are not displayed.

BreZygisk changes a persistent unmount marker. This is a broader setting, not a per-app choice. Nothing is selected automatically.

Configure or fetch a private source

Put a JSON configuration in the root-private inbox: directory mode 0700, file mode 0600. Enter only its path. Keep URLs, credentials and file contents outside this UI.

Saving configuration and checking status do not fetch a feed. Fetch stages a copy; it does not select keys or apply changes.

Local import remains available. No uploaded key material, automatic fetch, selection, Plan or Apply.

Fingerprint and patch warnings

Manual, read-only check. The supplied 2026-11-18 Canary expiry is an estimate; a changed fingerprint invalidates it.

Recover an interrupted change

Restore files or release an ended lock

Inspect the recovery state first. Restoration returns the interrupted transaction’s previous configuration.

A lock can be released only after the backend proves its process ended or the boot changed. A running process’s lock is kept.

Wallet app-data reset

Cleared app data cannot be restored by a configuration backup.

Review a destructive reset

This clears Wallet, Play Store, GSF and GMS app data. Card setup may be lost; Google sign-in and card setup may need repeating. GSF state and Android-ID behavior may change.

Use only after diagnosis supports this separate workflow. A manual reboot and reviewed PIF action follow. The requested second GMS clear has no established rationale.

Finish a reviewed reset after reboot

Automatic PIF execution is unavailable. The installed action fetches network material and can change PIF and patch settings. Review and run it manually, then force-stop GMS. Do not repeat the clears.

Close an incomplete reset without repeating it

Inspect reset state first. This preserves the attempted-step ledger and backup. It does not repeat clears or restore cleared app data.
